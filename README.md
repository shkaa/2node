# 2node

Запасной VPS, если текущий адрес перестанут пускать. Скрипт ставит книжный сайт и проброс на основной сервер. Учётка остаётся на основном, здесь она не создаётся.

На основной сервер этот скрипт запускать нельзя. Он сам останавливается, если на машине уже есть naive.

## Запуск

Новый чистый Ubuntu, root:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/shkaa/2node/main/install.sh)
```

Репозиторий для этой ссылки должен быть публичным.

Скрипт спрашивает:

- IP основного сервера. Enter оставляет `89.127.213.243`.
- Имя в ссылке. Enter оставляет `kakamba.work.gd`. Сертификат этого имени лежит на основном, его не меняют.
- Домен сайта на этом VPS. Enter оставляет `gosuslugi.win`.
- Логин и пароль учётки. Они только чтобы собрать строку для клиента и показать её на экране. В файлы, в git и в настройки сервера пароль не пишется. Пустой логин — ссылку не собирает, печатает только новый `?ip=`.

Тот же скрипт с диска, без вопросов, если значения уже заданы:

```bash
ORIGIN=89.127.213.243 RELAY_NAME=kakamba.work.gd SITE_DOMAIN=gosuslugi.win bash install.sh
```

## Что получается

- 443 принимает nginx. Запрос с именем сайта уходит на локальную страницу. Любое другое имя, включая имя из ссылки, уходит на основной сервер, порт 443.
- Сайт слушает Caddy на `127.0.0.1:8443` и забирает сертификат через 80 порт.
- В клиенте меняется только хвост ссылки: `?ip=` плюс адрес этого VPS. Логин, пароль и имя хоста те же.

Пример:

```text
naive+https://LOGIN:PASSWORD@kakamba.work.gd:443?ip=АДРЕС_НОВОГО_VPS
```

Эту строку вставляешь в телефон и в Windows. Отдельно hosts не нужен.

Сертификат сайта появится, когда A-запись домена смотрит на новый VPS и прокси облака выключено. Проброс для клиента от этой записи не зависит: клиент ходит на IP напрямую.
